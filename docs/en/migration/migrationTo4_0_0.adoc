= v4.0.0

== Changes

=== Default eviction action

`coffee-rest` provides a default `@ApplicationScoped` CDI `EvictAction` extending `AbstractEvictAction`.
`ISystemRest.getEvict()` is now an abstract endpoint declaration; it contains no action invocation.
`AbstractWildFlySystemRest.getEvict()` and `AbstractQuarkusSystemRest.getEvict()` now invoke it
through `wrapNoParam`. Without an application override, `GET /system/evict` now clears caches
instead of reporting that eviction is not implemented.

.Migration
For the default behavior, application-level eviction actions and delegating `getEvict()` overrides are no longer required.
Classes implementing `ISystemRest` directly must implement `getEvict()` or extend the appropriate abstract system REST class.
Existing endpoint overrides continue to work. To customize the inherited endpoint via CDI,
extend `hu.icellmobilsoft.coffee.rest.action.evict.EvictAction` and annotate the subclass with
`@Alternative`, `@Priority` and an explicit CDI scope, such as `@ApplicationScoped`.
Call `super.evict()` to retain the default behavior.
See <<common_core_coffee-rest,coffee-rest>> for an example.

=== coffee-module-wildfly and coffee-module-wildfly-management

* The management module's server API versions are managed centrally by `coffee-bom-all`,
aligned with WildFly 41.0.1.Final: WildFly Core 33.0.1.Final, Undertow 2.4.3.Final and JBoss MSC 1.5.6.Final.
WildFly Core and the full WildFly distribution have separate version numbers.
* The new optional `coffee-module-wildfly-management` module exposes the WAR manifest
on the WildFly HTTP management interface, at `GET /version` by default.
* The `AbstractWildFlySystemRest.versionInfo()` Java method is deprecated;
the existing `/versionInfo` REST endpoint remains available for compatibility.
* Both endpoints use `ManifestUtil.getManifestContent(InputStream)` from `coffee-se-util`,
with explicit UTF-8 encoding. The caller obtains the manifest stream from `ServletContext`;
the utility itself has no Servlet or WildFly API dependency and closes the supplied stream.
Line order, continuation lines and sections are preserved, with line endings normalized to LF.

.Migration
To enable the management endpoint, add the `coffee-module-wildfly-management` dependency,
create an `@ApplicationScoped` subclass of `AbstractWildFlyManagementVersionInfo`, and expose
the required server modules in `jboss-deployment-structure.xml`.
For multiple deployments, override `protected getPath()` to select a unique path.
See the <<common_module_coffee-module-wildfly-management,coffee-module-wildfly-management>>
documentation for configuration details and examples.

Applications importing `coffee-bom-all` do not need to specify the managed server API versions separately.
The server API dependencies retain `provided` scope and must be supplied by the target WildFly server.
Existing callers of `AbstractWildFlySystemRest.versionInfo()` require no changes for the shared manifest reader.

Following the removal of `AbstractSystemRest`, `AbstractWildFlySystemRest` extends
`BaseRestService` directly and implements `ISystemRest`.
Existing subclasses of `AbstractWildFlySystemRest` do not need updating because of this change.

=== Package rename of WildFly and Quarkus modules

The misspelled `hu.icellmobilsfoft` package prefix was corrected to `hu.icellmobilsoft`
in `coffee-module-wildfly` and `coffee-module-quarkus` (breaking change).
The class names did not change; the new `coffee-module-wildfly-management` module uses the corrected package from the start.

.Migration
Update the imports in the project:

* `hu.icellmobilsfoft.coffee.module.wildfly.rest.system.AbstractWildFlySystemRest` -> `hu.icellmobilsoft.coffee.module.wildfly.rest.system.AbstractWildFlySystemRest`
* `hu.icellmobilsfoft.coffee.module.quarkus.rest.system.AbstractQuarkusSystemRest` -> `hu.icellmobilsoft.coffee.module.quarkus.rest.system.AbstractQuarkusSystemRest`

=== coffee-model-base

* The `IAuditEntity` interface no longer extends the `IVersionable` interface.
* `AbstractEntity` now contains only the `id` field (`X__ID`, `@CoffeeIdGenerator`) and implements the `IIdentifiedEntity<String>` interface.
The `version` field and the version management methods (`rollbackVersion()`, `updateVersion()`) have been removed from it, and it no longer implements the `IVersionable` interface.
* New `AbstractVersionableEntity` class: a subclass of `AbstractEntity` that contains the `version` (`X__VERSION`, `@Version`) field and the version management methods. It implements the `IVersionable` interface.
* New `AbstractVersionableAuditEntity<T extends Serializable>` class: a subclass of `AbstractAuditEntity` with version management (`IVersionable`).
* The `hu.icellmobilsoft.coffee.model.base.AbstractAuditEntity` class now uses `OffsetDateTime` typed `creationDate` and `modificationDate` fields, without `@Temporal`. The type parameter is `T extends Serializable`.
* The following classes have been removed: `AbstractIdentifiedEntity`, `AbstractIdentifiedAuditEntity`, and the `AbstractAuditEntity` and `AbstractIdentifiedAuditEntity` classes of the `javatime` package.

.Migration
Update the superclasses and imports according to the table below:

[cols="1,1",options="header"]
|===
|Previous class |New class
|`model.base.AbstractIdentifiedEntity` |`model.base.AbstractVersionableEntity`
|`model.base.AbstractIdentifiedAuditEntity` |`model.base.AbstractVersionableAuditEntity<String>`
|`model.base.javatime.AbstractAuditEntity` |`model.base.AbstractAuditEntity`
|`model.base.javatime.AbstractIdentifiedAuditEntity` |`model.base.AbstractVersionableAuditEntity<String>`
|===

Attention:

* `model.base.AbstractAuditEntity` inherits the `id` field from `AbstractEntity`, so `X__ID` becomes the primary key even when the entity extends it directly. If this is not desired, derive the entity from a different superclass, or adjust the database schema accordingly.
* If the entity requires version management, it should extend `AbstractVersionableEntity` or `AbstractVersionableAuditEntity`.
* The `precision = 20, scale = 0` specification has been removed from the `X__VERSION` column definition. Schema generation or schema validation may report differences.
* Where code uses `getVersion()` through an `AbstractEntity` reference, switch the type to `IVersionable`.

=== coffee-model-security

* The `SecurityGroup`, `SecurityPermission`, `SecurityRole`, `SecurityRoleSecurityGroup`, `SecurityRoleSecurityPermission`, `SecurityUser`, `SecurityUserSecurityGroup` and `SecurityUserSecurityRole` entities now extend `AbstractVersionableAuditEntity<String>`.

.Migration
Replace the `AbstractIdentifiedAuditEntity` superclass with `AbstractVersionableAuditEntity<String>`, together with the import.

=== coffee-module-document

* The `TemplateData` and `TemplateParameter` entities now extend `AbstractVersionableAuditEntity<String>`.
* The `validFrom` and `validTo` fields of `TemplateData` are `OffsetDateTime` typed, without `@Temporal`.

.Migration
Replace the superclass with `AbstractVersionableAuditEntity<String>`. The types of the `validFrom` and `validTo` getters and setters must be changed from `Date` to `OffsetDateTime`.

=== coffee-module-notification

* The `Email`, `EmailRecipient`, `Push`, `PushDevice` and `Recipient` entities now extend `AbstractVersionableAuditEntity<String>`.
* The `Email.sentTime` and `PushDevice.sentTime` fields are `OffsetDateTime` typed, without `@Temporal`.
* `EmailHelper` and `PushHelper` set the sending time using `DateUtil.nowUTC()` instead of `new Date()`.

.Migration
Replace the superclass with `AbstractVersionableAuditEntity<String>`. The types of the `sentTime` getters and setters must be changed from `Date` to `OffsetDateTime`.

=== coffee-system-jpa

* The generic bound of `Converter` and `DtoConverter` is now `IVersionable` (previously `AbstractEntity`).
* The generic bound of `DtoAuditConverter` is now `IAuditEntity<OffsetDateTime, String> & IVersionable` (previously `javatime.AbstractAuditEntity<String>`).
* The parameter of `CommonIdListTypeConverter.convert(...)` is now `IIdentifiedEntity<String>` (previously `AbstractIdentifiedAuditEntity`).

.Migration
Update the generic bounds of your own converters and the imports according to the changes above.

=== coffee-tool
* `hu.icellmobilsoft.coffee.tool.utils.json.JsonUtil` now contains only JSON-B-based conversions
and can be used without Gson.
* Gson-based operations have moved to `hu.icellmobilsoft.coffee.tool.utils.json.GsonUtil`,
which remains in the `coffee-tool` module.
* The `com.google.code.gson:gson` dependency is optional (`optional=true`) in the `coffee-tool` POM.
It remains available when compiling and testing `coffee-tool`, but is no longer added automatically
to a consuming application's classpath through this dependency.
Other dependencies, such as `coffee-module-redis` or `coffee-module-mongodb`, may still bring in Gson.

.Migration
The previous Gson-based methods, including the already deprecated methods, have been removed from `JsonUtil`.
This is a breaking API change: code using these methods must be updated and recompiled.
Method names and parameters are preserved in `GsonUtil`; the following replacements also apply to overloads.

[cols="1,1",options="header"]
|===
|Previous call |Replacement
|`JsonUtil.getGsonConfig()` |`GsonUtil.getGsonConfig()`
|`JsonUtil.toJsonGson(...)` |`GsonUtil.toJsonGson(...)`
|`JsonUtil.toObjectGson(...)` |`GsonUtil.toObjectGson(...)`
|`JsonUtil.toObjectUncheckedGson(...)` |`GsonUtil.toObjectUncheckedGson(...)`
|`JsonUtil.toObjectUncheckedEx(...)` |`GsonUtil.toObjectUncheckedEx(...)`
|`JsonUtil.toObjectUnchecked(...)` |`GsonUtil.toObjectUnchecked(...)`
|`JsonUtil.toJsonEx(...)` |`GsonUtil.toJsonEx(...)`
|`JsonUtil.toObjectEx(...)` |`GsonUtil.toObjectEx(...)`
|===

When using Gson, declare it as a direct application dependency:

[source,xml]
----
<dependency>
    <groupId>com.google.code.gson</groupId>
    <artifactId>gson</artifactId>
</dependency>
----

This example assumes that `coffee-bom-all` dependency management is imported, which manages the Gson version.
If the application's dependency management does not manage Gson, specify a version as well.
Gson must also be available at runtime when using `GsonUtil` or the `hu.icellmobilsoft.coffee.tool.gson` adapters.

[source,java]
----
import hu.icellmobilsoft.coffee.tool.utils.json.GsonUtil;

String json = GsonUtil.toJsonGson(dto);
MyDto result = GsonUtil.toObjectGson(json, MyDto.class);
----

The JSON-B-based `JsonUtil.toJson(...)`, `toObject(...)`, `toObjectOpt(...)` and `getJsonbContext()` calls do not need updating
and do not require adding Gson. The JSON-B API and an implementation are still required.
When switching from Gson to JSON-B, review formats, adapters and annotations separately;
the two serializers do not always behave identically.
